# 赛季状态与结算定时任务

> **文档目的**
>
> 本文档说明管理端后端如何定时推进到期赛季、持续执行常规结算，并在配置期限后自动一键收口。

## 1. 功能目标

任务负责以下生命周期：

```text
0 未开始 → 1 进行中 → 2 结算中 → 3 已结束
```

应用启动后立即执行一次，随后按固定间隔轮询。服务停机、外部初审失败或单个用户结算失败都可以由后续轮询补偿，不要求人工重新触发整个赛季。管理员可以启用自动一键结算，在赛季结束后的指定业务日期强制结束仍未收敛的结算赛季。

---

## 2. 触发与时间口径

任务使用 `Asia/Shanghai` 业务日期，并将 `season.end_date` 视为赛季有效期内的最后一个完整自然日。进入结算条件为：

```text
season.status = 1
AND season.end_date < Asia/Shanghai 当前日期
AND 当前不存在 status = 2 的赛季
```

未开始赛季自动激活的条件为：

```text
season.status = 0
AND season.start_date <= Asia/Shanghai 当前日期
AND season.end_date >= Asia/Shanghai 当前日期
AND 当前不存在 status = 1 的赛季
```

一个 `status = 2` 的结算中赛季可以与一个 `status = 1` 的进行中赛季同时存在，不会阻止新赛季按日期激活。已经错过结束日期且仍为未开始的异常赛季不会被追溯激活，避免短暂开放已经过期的赛季。

赛季截止时刻按结束日期下一日 `00:00:00` 解释。遗留初审只扫描 `proof_record.created_at` 严格早于该时刻的有效正式参赛凭证。

自动一键结算日期按上海自然日计算：

```text
auto_complete_date = season.end_date + SEASON_SETTLEMENT_AUTO_COMPLETE_AFTER_DAYS
```

仅当赛季仍为 `status = 2` 且当前业务日期大于或等于该日期时执行。配置 `0` 表示赛季进入结算中后的首次轮询即可执行；例如结束日为 7 月 31 日、配置 `7`，则从 8 月 7 日的首次轮询开始执行。

## 3. 配置

| 配置 | 默认值 | 约束 | 说明 |
| --- | ---: | ---: | --- |
| `SEASON_STATUS_CHECK_ENABLED` | `true` | 布尔值 | 是否启动后台任务 |
| `SEASON_STATUS_CHECK_INTERVAL_SECONDS` | `60` | `1～86400` | 每轮结束后的等待秒数 |
| `SEASON_SETTLEMENT_REVIEW_BATCH_SIZE` | `100` | `1～1000` | 单批遗留初审凭证数 |
| `SEASON_SETTLEMENT_REVIEW_CONCURRENCY` | `5` | `1～50` | 单进程初审并发数 |
| `SEASON_SETTLEMENT_USER_BATCH_SIZE` | `100` | `1～1000` | 单批未定分用户数 |
| `SEASON_SETTLEMENT_AUTO_COMPLETE_ENABLED` | `false` | 布尔值 | 是否在配置日期自动执行一键结算 |
| `SEASON_SETTLEMENT_AUTO_COMPLETE_AFTER_DAYS` | `7` | `0～365` | 赛季结束日后等待的自然日数 |
| `SEASON_SETTLEMENT_TWO_MONTH_STREAK_BONUS_POINTS` | `50` | `0～4294967295` | 连续完整完成两个月的额外积分 |
| `SEASON_SETTLEMENT_THREE_MONTH_STREAK_BONUS_POINTS` | `100` | `0～4294967295` | 连续完整完成三个月及以上的额外积分 |

所有配置在应用启动时加载，修改后需要重启服务。自动一键结算依赖 `SEASON_STATUS_CHECK_ENABLED = true`；独立开关默认关闭，避免新版本部署后未经确认自动结束现有结算赛季。

连续奖励调整只影响尚未定分的用户；三个月档替代两个月档，不叠加发放。挑战等级积分与连续奖励之和超过 `season_user.final_points` 的存储范围时，该用户本轮定分失败，任务记录错误并在后续轮询重试。

## 4. 执行流程

1. 锁定并检查当前结算中赛季。
2. 若不存在结算赛季，锁定唯一到期赛季，将其更新为结算中，并在同一事务清空补传资格表。
3. 独立锁定未结束赛季；不存在进行中赛季时，将当前日期范围内唯一的未开始赛季激活。
4. 获取当前结算赛季截止前遗留的待初审凭证。
5. 在事务外分批并发调用客户端后端立即初审接口。
6. 数据库仍有遗留 `pending` 时结束本轮，不执行用户定分。
7. 查询资格状态为 `2` 的补交记录，在事务外分批并发调用客户端后端补交专用初审接口；仍有待审记录时结束本轮。
8. 分页处理所有未定分正式参赛用户，先拒绝已确定达标项目的额外待终审凭证，再为剩余待终审凭证创建资格或写入最终积分。
9. 确认不存在未定分、积分未发放用户和非零资格后，将赛季更新为已结束。
10. 若赛季仍在结算中、自动开关已启用且达到配置日期，复用一键结算事务拒绝全部未审核凭证、重算进度、清空补传资格表、定分、发放积分并结束赛季。

详细分支参见[赛季结算应用编排](../application/season-settlement.md)与[赛季结算规则](../domain/season-settlement.md)。

## 5. 事务、并发与幂等

- 赛季首次状态更新和资格表清空在同一事务中完成；后续轮询不会再次清空。
- 自动激活在独立事务中锁定全部未结束赛季，并以 `status = 0` 条件更新；重复轮询不会重复激活，多个进行中赛季或多个到期候选会使本轮回滚并记录异常。
- 单赛季约束通过锁定查询执行，多个结算中赛季会使任务停止写入。
- 外部 HTTP 调用期间不持有数据库事务或连接。
- 每个用户使用独立事务并锁定 `season_user`，避免并发终审重复定分。
- 资格使用凭证唯一键幂等写入，首次创建固化初审上下文，重复开放不覆盖快照；定分使用 `final_points IS NULL` 条件写入。
- 赛季结束使用带完整性条件的状态更新，同时检查 `final_points` 和 `points_issued`，重复执行不会越过目标状态。
- 自动收口直接复用管理接口的一键结算服务；凭证、进度、补传资格整表删除、定分、积分流水和赛季状态共享一个事务。
- 多个任务实例同时到期时，用户、赛季和参与记录锁保证只有一个请求提交；其他实例重新读取到已结束状态后保持无操作。

---

## 6. 异常与监控

- 单轮未捕获异常会记录堆栈，任务等待下个周期后继续。
- 外部初审失败只记录凭证 ID 和安全错误信息，不把失败解释为审核拒绝。
- 单个用户数据不一致时回滚该用户事务，记录赛季用户 ID，并继续处理其他用户。
- 自动一键结算任一步失败时整体回滚，任务记录异常并在下个轮询周期重试；不会把失败解释为部分成功。
- 应用退出时取消任务，再关闭共享 HTTP 客户端和数据库连接池。
- 当前使用应用日志和每轮汇总记录工作量，尚无独立任务执行表和监控指标。

## 9. 已知限制

- 任务依赖管理端后端进程运行，停机期间由下次启动补偿。
- 客户端已提供补传查询和提交接口，但尚无补传截止时间或次数限制；自动一键结算关闭时，存在非零资格的赛季不会自动结束。
- 任务没有持久化外部调用重试次数，凭证保持 `pending` 时由周期任务重新尝试。
