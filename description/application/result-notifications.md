# 业务结果通知写入

> **文档目的**
>
> 本文档说明管理端在凭证终审拒绝和礼品发放审核完成后创建 Markdown 工作通知的规则与事务边界。

## 1. 功能目标

管理端后端将需要发送的业务结果写入 `notification` 表，不直接调用钉钉接口。客户端后端负责读取 `pending` 通知、发送 Markdown 工作通知并更新投递状态。

---

## 2. 通知内容

当前通知内容如下：

| 业务场景 | 通知标题 | 消息字段 |
| --- | --- | --- |
| 凭证终审拒绝 | `运动凭证终审结果` | 审核结果、运动项目、凭证日期、审核意见 |
| 奖品确认发放 | `奖品发放结果` | 发放结果、奖品名称、兑换时间 |
| 奖品拒绝发放 | `奖品发放结果` | 发放结果、奖品名称、兑换时间、退还积分、处理说明 |

凭证终审通过不创建通知。终审拒绝未填写审核意见时，通知中的审核意见使用 `未填写`。

---

## 3. 写入流程

通知记录的初始值固定为：

```text
task_id = NULL
notification_status = pending
```

终审拒绝把凭证状态更新、项目进度回退、候选凭证回补、项目进度写回和通知创建放在同一个事务中。

礼品确认发放把兑换流水终态更新和通知创建放在同一个事务中。礼品拒绝发放还会在该事务中更新原兑换流水并新增 `exchange_refund` 积分流水。

---

## 4. 幂等与失败处理

- 只有仍处于 `preliminary_approved` 的凭证可以终审，因此同一终审拒绝不会重复创建通知。
- 礼品发放只在 `pending` 首次转换为 `distributed` 或 `rejected` 时创建通知。
- 重复提交相同礼品终态按幂等成功处理，不重复创建通知。
- 礼品终态冲突不创建通知。
- 通知写入失败时，当前业务事务整体回滚。

## 7. 已知限制

- 本仓库只负责创建通知，不包含客户端后端的钉钉发送与状态轮询实现。
- 通知保存发送时的展示快照，不保存来源业务记录 ID。
- 奖品名称来自通知创建时的当前商品名称，历史兑换流水没有单独保存兑换时商品名称。
